# obsidian-ui — evaluation, 2026-08-03

Reviewed at commit `1878790` ("feat: build module-first Obsidian app"), clean tree.
Everything below was verified by running the code and reading the real manifest,
not from the READMEs.

## Verdict

**The engineering is done. The product is half-built, and it has never been used.**

The boundary discipline is real and the plumbing works end-to-end. What's missing
isn't polish — it's the entire decision layer. The core already *computes* what
Aram should do next; the app renders the curriculum tree and drops that on the
floor. And the write path has zero real invocations: it's green against a
synthetic fixture and untouched against actual study data.

## Gap 1 — the app browses the curriculum; it doesn't run the semester

The core computes a decision layer. The app renders none of it.

**`workspace.next_action` is already in the manifest** — every one of the 8 workspace
records carries `next_action`, `status`, `standing`, `deadline`. This is the single
most valuable computed field in the whole system:

> `workspace-amls-exam-prep` → "Session 1 of the S.X track: lecture 03 (Size Inference,
> Rewrites, Operator Selection) — mp4 + slides, then MLC tensor-program chapter, then
> 10-414 HW1 autodiff parts as drill."

In the app this appears **nowhere**. Workspaces are chips at the bottom of the module
page, and clicking one calls `openRecord` → `record.path` → opens raw `CONTEXT.md`
as a markdown wall. That's the exact failure `CLAUDE.md` hard rule 13 was written
to prevent.

**The coordination record is structured and unused.** `records[type=coordination]`
carries `COORDINATION.md` as parsed `sections` (Commitments, Priorities, Deferrals).
Zero surfaces read it. The priorities decision of 2026-07-25 — "the exams are the
super-priority, thesis becomes primary after M2" — is invisible in the interface.

**Home's exam strip is structurally blind to the deadlines that matter.**
`renderAcademic()` renders `exam_spine`, and `_exam_spine()` filters to
`result == "registered"`. Today exactly one attempt qualifies: AMLS 2026-08-27.
Invisible in the app:

- AML 2. Termin — Mi 2026-09-30
- M2 Kombi Klausur — Fr 2026-10-09
- Algo 2 oral window — 2026-10-05 to 08
- **2.-PZ Anmeldung window 2026-08-31 → 2026-09-10**, which gates all three

That window opens in four weeks and the app's only calendar surface shows one date.
The facts exist — as prose in `examination.notes`, rendered by
`coordination-view.md` under "Enrolled, no registered attempt yet." Fixing this is
a **core-first** change (structured sitting / Anmeldung fields → manifest → view),
per hard rule 9.

**Also unsurfaced:** the Garden/Nebula (`CLAUDE.md` §14 — `bases/garden.base` is
installed but there's no nav entry), `domain-atlas.md` (mandated by bootstrap §2.8
and ADR-005), and `los.py capture` — the Inbox view prints a count and tells you to
use the CLI, so WORKFLOWS §2 and §21 are unreachable from the app.

## Bugs and risks

**1. `main.ts` `runLos()` — hardcoded venv, no fallback.**

```js
const bundled = nodePath.join(base, '.venv', 'bin', 'python');
const python = bundled;            // dead indirection; no fallback branch
```

The core README documents the opposite contract: "use `.venv/bin/python` when it
exists, and fall back to the system `python3` otherwise." Before `make setup` on any
clone, every write button dies with a raw ENOENT notice. Worse, `.venv/pyvenv.cfg`
pins an absolute Homebrew path (`python@3.14`) under the user's home directory,
so it breaks on the folder move the core README explicitly anticipates.

**2. `main.ts` `reloadStore()` — `this.app.workspace._leaves` is not an Obsidian API.**

The test harness *defines* `_leaves` (`harness.js:280`), so the test is green. In
real Obsidian it's `undefined`, `|| []` swallows it, and no sibling view re-renders
after a mutation. Symptom: complete a stage in the unit view, and Home still shows
the old count until you reopen it. Fix: `this.app.workspace.iterateAllLeaves()`.

**3. `unit-view.ts` attachment picker — `file.path` is gone.**

Electron removed `File.path` in v32 (`webUtils.getPathForFile()` replaced it). No
test covers `stage-attach`. This button is likely dead on current Obsidian —
handwriting capture is exactly the workflow that most needs it.

**4. The boundary test is grep-on-bundle.** `!/vault\.modify\s*\(/` and friends are a
fine regression tripwire but prove nothing under indirection. Worth being clear-eyed
about what they guarantee.

**5. The "TypeScript" claim is overstated.** No file in `src/` has a single `import`;
`Plugin`, `ItemView`, `Notice`, `execFile`, `nodePath` are injected by a string
header in `build.mjs`. `tsc --noEmit` would fail on every file despite
`tsconfig.json` claiming to check them. The test "bundle is generated from modular
TypeScript" only asserts that ≥8 files exist in `src/views/` and that `build.mjs`
mentions one of them. Separately, the build's `.replace(/^export\s+/gm, '')` will
strip the word "export" from any string or comment at line start — a latent
footgun. This is fine as an approach; the *labelling* is what's wrong.

## Redundancies found and removed in this pass

**`exam_spine` retired from the manifest.** It listed only `result: registered`
attempts — a strict subset of `academic_deadlines`, in a second shape, carrying a
third copy of `examination.notes`. The UI's only use was an unreachable fallback
that re-derived the core's projection shape client-side; both are gone.
`_exam_spine()` survives behind the Markdown views and `los.py status --json`,
which answers the narrower "what am I registered for" and has its own test.

**`stages` promoted from dead weight to a declared index.** 66 stages were
projected flat (with `study_map_id`/`unit_id`/`module_id`) and read by nobody
while the app hand-walked `study_maps[].stages`. Now the flat array is the by-id
index — `store.stage(id)` resolves from an ID alone — and the nested list stays
the ordering authority for the stage rail and progress counts. Index plus ordered
list, never two traversals of the same access path.

**Prose duplication eliminated.** Every date restated in `examination.notes` was
first *moved into structure* (AML and M2 gained their 1.-Termin sittings; AMLS
gained all three course-run slots), then removed from the prose. Nothing was
deleted — the notes now carry only what the schema cannot hold: plan of record,
Prüfungsplan verification stamps, Übungen-ungraded, and the TU-Nebenhörer
registration path. One fact, one home.

**Fixture drift closed.** `fixture-vault/generated/manifest.json` was missing the
top-level `stages` key the real contract emits — the same class of gap that let
the `_leaves` bug pass green. A new test derives every top-level key the bundle
reads and asserts the fixture declares it.

## Bug found while cleaning

**`los.py session-end` validated the wrong repository.** `validate.py` resolves
its root from its own file location unless given `--root`; `cmd_session_end`
passed only `cwd=root`. So closing a session in repo A gated on the cleanliness
of whichever repo the tools live in. Invisible in normal use (same repo), fatal
for any other root — and it made the canvas session-end test pass only by
accident. Fixed, with an assertion that the validation report lands in the root
the session actually touched.

## Contract note

`contract_version` stays `2`: both layers ship together, there is exactly one
manifest consumer and it was updated in the same pass. Recorded in ADR-006 as the
fifth addendum, along with the rule that was previously only implicit — *where a
projection could be expressed two ways, the manifest carries exactly one* — and
the requirement that the next removal landing without a matching UI change must
bump the version.

## Installer: Node discovery

`install.py` refused to run because `shutil.which("node")` was empty — a
GUI-launched or bare shell often has no Node on PATH, and the README papered over
it by hardcoding a path into `~/.cache/codex-runtimes`, which is a cache and can
vanish. The installer now searches PATH, `/opt/homebrew/bin`, `/usr/local/bin`,
`/usr/bin`, `~/.nvm`, `~/.volta` and bundled agent runtimes, logs which binary it
chose, and lists everywhere it looked if it finds none. `--node` still overrides.
The README no longer contains a machine-specific path.
